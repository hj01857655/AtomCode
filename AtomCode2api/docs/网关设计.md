# atomcode2api 设计文档

> 日期：2026-09-30（**2026-10-09 修订**：签名关卡证伪，见 [03-data-plane.md](atomcode-03-数据面与UA门.md)；**2026-10-10 修订**：已按 Python 落地实现，与本文初版设计的差异见 §12）
> 状态：已实现（`server.py` + `auth.py`，Flask 单文件网关；逆向事实见 [README.md](README.md) 索引）
> 定位：把 AtomCode（GitCode/AtomGit CodingPlan 套餐，官方 CLI 专属额度）反代为
> 本地 OpenAI/Anthropic 双协议兼容 API，可部署在任意机器/服务器。

## 1. 目标

- 客户端（Claude Code / Cline / Cherry Studio / 任意 OpenAI 或 Anthropic SDK）通过
  `Bearer <API_KEY>` 访问本网关，网关消耗已登录 AtomCode 账号的 CodingPlan 额度。
- 多账号池轮询 + 5h 窗口额度可视化 + 401 自动 token 刷新 + 故障自动转移。
- 上游数据面：`https://api-ai.gitcode.com/v1`（OpenAI 格式 + SSE；**免签名**）。
  官方默认的 `llm-api.atomgit.com/v1` 不可用（要求闭源签名，换 UA 也 403，见
  [03-data-plane.md](atomcode-03-数据面与UA门.md)）。
- 硬约束：聊天请求**不得携带 `atomcode/*` 的 User-Agent**——那是签名门的开关。
- 上游控制面：`api.gitcode.com/api/v5/coding-plan/*`（免签名，Bearer token）。

### 明确不做（YAGNI）

- 不做 Responses API。
- ~~不做 OAuth 登录全流程~~ **2026-10-10 已实现**：`GET /login` + `GET /login/poll`（acs.atomgit.com
  平台代持流，无需 client_id/PKCE，源码坐标 `oauth.rs`），凭据写入 `~/.atomcode/auth.toml`。
- 主凭据模型：直接共用官方 CLI 的 auth.toml（mtime 热加载跟随 CLI 刷新/重登），不做独立的
  粘贴 token 导入。

## 2. 架构

```
客户端（任意 OpenAI/Anthropic SDK）
    │  Bearer <API_KEY>
    ▼
atomcode2api（127.0.0.1:8788，可配端口）
    ├─ protocol/     双协议编解码（上游原生 OpenAI；Anthropic 客户端做转换）
    │                + SSE 透传/回放 + reasoning_content → thinking block 映射
    ├─ accounts.js   账号池：round-robin + X-Session-Id 亲和
    │                每个账号 = {accessToken, refreshToken, userId, username,
    │                planType, windows, expiresAt}（accounts/*.json，.gitignore）
    ├─ upstream.js   聊天转发（免签名）：固定 api-ai.gitcode.com + 非 atomcode UA
    ├─ auth/         token 存储（原子写）+ 401 时 POST acs.atomgit.com/oauth/refresh
    │                （RT 轮换，刷新成功即原子回写新 RT）
    ├─ quota.js      status-v2 轮询（默认 60s）：窗口剩余额度、reset_at 倒计时、
    │                套餐到期日；额度将尽 → 该账号降权/跳过
    └─ dashboard/    单页看板（账号池、窗口水位、事件流、模型目录）
```

## 3. 核心流程

### 3.1 聊天请求

1. 模型名归一：客户端 `claude-*`/别名 → 账号可用模型（models-v2 目录动态下发，
   不再硬编码 zcode2api 式的 glm 映射表；`claude-sonnet-*` 默认映射到目录里
   context 最大的模型，可配）。
2. 账号池 pick：round-robin + `X-Session-Id` 亲和（TTL 2h）；跳过：
   窗口额度耗尽（`remaining==0` 且未到 `reset_at`）、`expiresAt` 过期、
   `needsRelogin`、冷却中。
3. 构造 OpenAI body（`stream` 按客户端透传）→
   `POST /v1/chat/completions`（host 走 `LLM_BASE_URL`，默认 `https://api-ai.gitcode.com/v1`；
   **不签名、不带 `atomcode/*` UA**）。
4. 响应处理：
   - `200` → SSE 透传（OpenAI 客户端）/ 转 SSE（Anthropic 客户端）；
     `reasoning_content` → Anthropic thinking block；流末 usage 记账。
   - `401` → `refresh(account)`：成功则原 body 重发一次；失败标记
     `needsRelogin` 换号（≤2 次换号）。
   - `429`/窗口耗尽类 → 该账号冷却至 `reset_at`，换号重试（≤2 次）。
   - `403` → 先查是不是自己误带了 `atomcode/*` UA（那是签名门）；确认不是后再按
     账号权限处理，换号；全不支持 → 503 带原因。
5. 全池不可用 → 503 + 原因（全部冷却/过期/需重登/额度耗尽）。

### 3.2 token 刷新（401 自愈 + 到期前主动刷新）

- 主动：`expiresAt - now < 24h` 时后台刷新。
- 被动：任意 401 立即刷新（账号级互斥锁，防并发刷新互相作废 RT——RT 轮换语义下
  双刷会互杀，**必须串行**）。
- 刷新失败：区分网络错（保持原 token 继续试）/ 认证错（`needsRelogin` + 看板告警）。
- 刷新成功：原子写回 `{accessToken, refreshToken, expiresAt}`。

### 3.3 额度轮询

- 每 60s（可配）对每个启用账号打 `status-v2?plan_type=<账号plan>`：
  更新 `windows[]`（`calls_used/call_limit/reset_at`）、套餐到期日。
- 看板展示：每账号窗口水位条 + `reset_at` 倒计时 + 总剩余可发请求数。
- 额度耗尽的账号在下次 `reset_at` 后自动恢复（下一轮询周期）。

### 3.4 账号导入

| 方式 | 适用 |
|---|---|
| 共用 `~/.atomcode/auth.toml`（**实际采用**）：mtime 热加载跟随官方 CLI，网关自身刷新/登录也原子写回此文件 | 与官方 CLI 共存的机器（当前部署形态） |
| ~~看板粘贴~~（初版设计，未实现——被共用 auth.toml + /login OAuth 取代） | — |

`user_id` 不再是签名输入（免签名，见 [03-data-plane.md](atomcode-03-数据面与UA门.md)），但仍是账号身份标识，
建议随 token 一起导入（auth.toml 的 `[user].id`；也可从任一控制面响应头 `x-uid` 自动回填）。

## 8. 错误处理

- 上游错误统一映射 `{status, code, msg}`，按客户端协议回传（OpenAI error object /
  Anthropic error object），保留上游 trace id。
- 账号级状态变化（刷新成功/失败、冷却、恢复、需重登）写看板事件流（最近 200 条）。
- 全池 503 时 body 给出**可操作原因**（例：`all accounts exhausted until 00:41:42`）。

## 12. 实际实现状态（2026-10-10）

初版设计（§2 架构树是 Node.js 规划）与实际落地（Python/Flask）的差异，以此节为准。

**已实现**（`server.py` + `auth.py`，Python 3.13）：
- OpenAI 兼容：`/v1/chat/completions`（流式/非流式）、`/v1/models`（models-v2 目录 + OpenRouter 列表聚合）、`/health`、`/status`（额度水位）
- 凭据：共用 `~/.atomcode/auth.toml`——mtime 热加载跟随官方 CLI；401 触发 RT 轮换刷新并**原子写回**（实测：刷新会同时作废旧 AT，故写回与热加载缺一不可）；进程内刷新互斥锁
- 自建 OAuth：`GET /login` + `GET /login/poll`（平台代持流，凭据写回 auth.toml）
- 启动自动 `claim-v2` 领取套餐
- 协议对齐上游官方 CLI：`stream_options.include_usage` 自动注入（流末 usage → 日志 tokens）；
  **OpenRouter 反代**（初版未设计的功能扩展）：`openrouter/*` 模型直连 OpenRouter，带官方同款
  app-attribution 头（`HTTP-Referer` + `X-Title`，免费模型 agentic 门必需）
- 日志：`server.log` 2MB 轮换；`[rNNNN]` 请求关联 ID + `in/done/ttft/tokens/client 断开`，werkzeug 访问行禁用

**未实现**（初版设计中的其余部分，按需再上）：
- Anthropic `/v1/messages` 双协议与 thinking 映射
- 多账号池 / 看板 / status-v2 后台轮询（当前单账号 + `/status` 即时查询够用）
- Responses API（明确不做）
